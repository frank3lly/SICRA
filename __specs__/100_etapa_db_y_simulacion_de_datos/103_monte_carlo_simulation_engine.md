## 1. Objective and Scope

Develop a standalone, high-performance simulation module in Python (`src/simulation/engine.py` and CLI `src/simulation/cli.py`) that implements **Monte Carlo probabilistic modeling** to generate realistic time-series telemetry data for the pilot Dominican businesses seeded in Subspec 102.

The engine must simulate between **20,000 and 100,000 records** covering 60 to 120 operational days. The generated data will emulate physical load cell readings, oil pouring events, weekly culinary demand cycles in the Dominican Republic, sensor noise, container emptying (*vaciados*), and battery voltage discharge over a 30-day autonomy cycle.

Every single record generated by this engine must have the database field **`is_synthetic = True`**.

## 2. Mathematical Modeling and Statistical Assumptions

```
                         MONTE CARLO PROBABILISTIC FLOW
                         
  ┌──────────────────┐       ┌──────────────────┐       ┌──────────────────┐
  │   Day of Week    │ ────► │ Customer Footfall│ ────► │ Daily Oil Pouring│
  │ Multiplier M(d)  │       │  Poisson(λ · M)  │       │   Gamma(k, θ)    │
  └──────────────────┘       └──────────────────┘       └────────┬─────────┘
                                                                 │
  ┌──────────────────┐       ┌──────────────────┐                ▼
  │  HX711 Reading   │ ◄──── │ Scale Weight (kg)│ ◄───── Cumulative Volume
  │ Gaussian Noise ε │       │  Tare + ρ·V + ε  │        Fill % & Drain Ev.
  └──────────────────┘       └──────────────────┘
```

### 2.1. Customer Footfall Simulation (Poisson Distribution)

Customer volume fluctuates by business type and day of the week:
$$\text{Customers}_{b}(t) \sim \text{Poisson}\left(\lambda_{b} \cdot M_{\text{day}}(t)\right)$$

Where $\lambda_{b}$ is the base average daily customer traffic from `businesses.avg_daily_customers`, and $M_{\text{day}}$ is the **Dominican Cultural Multiplier**:
* **Monday – Wednesday:** $0.75 - 0.85$ (Weekday baseline).
* **Thursday:** $1.00$ (Payday / pre-weekend lift).
* **Friday:** $1.65$ (*Viernes social*, surge in street frituras and beer kiosks).
* **Saturday:** $2.10$ (Peak Dominican fast food and chimi demand).
* **Sunday:** $1.80$ (Family dining, midday pica pollo rush).

---

### 2.2. Oil Disposal Generation (Gamma Distribution)

Oil disposal does not follow a symmetrical normal curve; it is right-skewed with occasional high-volume pot dumps. It is modeled using a **Gamma Distribution**:
$$\Delta V_{\text{oil}}(t) \sim \text{Gamma}\left(k=2.2, \, \theta = \frac{\mu_{\text{daily\_rate}}}{k}\right)$$

Where $\mu_{\text{daily\_rate}}$ is calculated from the business profile:
$$\mu_{\text{daily\_rate}} = \alpha_{\text{type}} \cdot \text{num\_fryers} \cdot \left(\frac{\text{Customers}_{b}(t)}{\lambda_{b}}\right)$$

* Coefficients by business type ($\alpha_{\text{type}}$):
  * **`PICA_POLLO`:** $3.5\text{ to }5.5\text{ Liters/fryer/day}$ (Heavy deep-frying of battered poultry).
  * **`FRITURA`:** $2.0\text{ to }3.5\text{ Liters/fryer/day}$ (Pork rinds, plantains, empanadas, sausages).
  * **`CAFETERIA`:** $0.8\text{ to }1.5\text{ Liters/fryer/day}$ (Light breakfast frying and turnovers).
  * **`RESTAURANTE`:** $1.0\text{ to }2.2\text{ Liters/fryer/day}$.

---

### 2.3. Accumulation, Load Cell Noise, and Draining Events

1. **Volume Accumulation:**
   $$V(t) = V(t-1) + \Delta V_{\text{oil}}(t)$$
2. **Gross Weight Calculation:**
   $$\text{Weight}_{\text{raw}}(t) = W_{\text{tare}} + \left(V(t) \cdot \rho_{\text{oil}}\right) + \epsilon_{\text{sensor}}$$
   * Density: $\rho_{\text{oil}} = 0.92\text{ kg/L}$.
   * Sensor measurement noise: $\epsilon_{\text{sensor}} \sim \mathcal{N}(\mu=0, \, \sigma=0.03\text{ kg})$.
   * Fill percentage: $\text{Fill\%}(t) = \left(\frac{V(t)}{V_{\text{capacity}}}\right) \cdot 100$.
3. **Emptying / Collection Logistics Simulation:**
   * When $\text{Fill\%}(t) \ge 80\%$, the container enters `ALERTA_80`.
   * Model a collection response delay: a collection truck visits within $12\text{ to }36\text{ hours}$.
   * When collection occurs:
     * $V(t_{\text{pickup}}) = V_{\text{residual}}$ (where $V_{\text{residual}} \sim \mathcal{U}(0.2, 0.6)\text{ Liters}$).
     * Tag reading with `flag = TelemetryFlag.DRAIN_EVENT`.

---

### 2.4. Battery Discharge Model (30-Day Autonomy Target - R-02)

Simulate two 18650 lithium cells in series/parallel discharging:
* Full charge: $4200\text{ mV}$.
* Nominal plateau: $3700\text{ mV}$.
* Cutoff alert: $3400\text{ mV}$.
* Linear/Sigmoidal degradation over a $35$-day cycle with random recharging/swapping events to emulate maintenance visits.

## 3. Architecture and Implementation Details

### 3.1. Engine Module: `src/simulation/engine.py`

* Class: `MonteCarloSimulator`
  * Constructor: `__init__(db_session, seed: int = 42)`
  * Use NumPy's recommended random generator:
    ```python
    self.rng = np.random.default_rng(seed)
    ```
  * Methods:
    * `simulate_business_timeline(container, start_date, days) -> List[Dict]`
    * `generate_synthetic_telemetry(days=90, interval_hours=2) -> int`

### 3.2. High-Throughput Bulk Persistence

Inserting $50,000+$ rows one by one through standard ORM sessions causes severe latency. The engine must use **SQLAlchemy Core Bulk Insert**:
```python
# Batch execution in chunks of 5,000 records
from sqlalchemy import insert
from src.models.entities import Telemetry

for chunk in chunk_iterator(telemetry_records, chunk_size=5000):
    db.session.execute(insert(Telemetry), chunk)
db.session.commit()
```

## 4. CLI Execution Specification (`src/simulation/cli.py`)

The simulator must be callable via terminal command:
```bash
python -m src.simulation.cli --days 90 --interval-hours 2 --seed 42 --output-csv data/synthetic/telemetry_simulation.csv
```

### CLI Arguments:
* `--days` (int, default `90`): Number of historical days to simulate.
* `--interval-hours` (int, default `2`): Periodic telemetry frequency.
* `--seed` (int, default `42`): Seed for exact mathematical reproducibility.
* `--to-db` (flag, default `True`): Persist directly into the database.
* `--output-csv` (str, optional): Also write the generated dataset to a standalone CSV file for data science inspection.

## 5. Verification and Test Criteria

1. **Deterministic Reproducibility Test:**
   * Running the simulation twice with `--seed 42` must produce identical numerical values down to the 4th decimal place.
2. **Performance Benchmark:**
   * Generating and writing $50,000$ telemetry rows must complete in under **10 seconds** on standard hardware.
3. **Physical Law Assertions:**
   * Assert $\text{raw\_weight} \ge W_{\text{tare}} - 0.1$ (no impossible negative volumes).
   * Assert all `is_synthetic` fields are strictly `True`.
   * Assert weekend generation ($\text{Fri} + \text{Sat} + \text{Sun}$) is statistically significantly higher than weekday generation ($\text{Mon} + \text{Tue} + \text{Wed}$) ($p < 0.01$).
